## 0. 一句话结论

上游是**双端 mod**（`environment: "*"` + `main` 入口点），它的网络层、服务端广播、平台抽象**我们全部用不上**；
但它的**交互设计、射线算法、屏幕投影、边缘指示、按键冲突处理**是 26.3 上最好的公开参考，**值得逐行抄**。
抄的是**算法与结构**（MIT 允许），不是**代码文本**（我们重写为无 Lombok、无平台抽象的纯客户端实现）。

**在原版服上的行为**（`PlatformNetworkServiceImpl.java:12-18`）：
```java
public void sendToServer(IPacket packet) {
    if (!ClientPlayNetworking.canSend(packet.getId())) {
        return;                      // 服务端没装 mod → canSend=false → 静默什么都不做
    }
    ClientPlayNetworking.send(packet);
}
```

**结论**：上游在"服务器不装 mod"的场景下**完全不可用**（按了没反应、也不报错）。这正是本项目要解决的问题。

## 3. 算法级借鉴清单（精确到行号）

> 以下每一条都是**独立可验证的算法**，抄的时候按行号对照。

### 3.1 世界 → 屏幕投影

**上游**：`common/.../math/MathUtils.java:14-31`

```java
public static ScreenPos worldToScreen(Vec3 worldPos, WorldRenderContext ctx) {
    var window = Game.getWindow();
    var worldPosRel = new Vector4f(worldPos.subtract(ctx.camera.pos).toVector3f(), 1f);
    ctx.modelViewMatrix.transform(worldPosRel);
    ctx.projectionMatrix.transform(worldPosRel);
    var depth = worldPosRel.w;                    // ← 关键：w 是"是否在相机前方"
    if (depth != 0) worldPosRel.div(depth);
    return new ScreenPos(window.getGuiScaledWidth()  * (0.5f + worldPosRel.x * 0.5f),
                         window.getGuiScaledHeight() * (0.5f - worldPosRel.y * 0.5f),
                         depth);
}
```

**为什么值得抄**：NDC（-1..1）→ 屏幕坐标的换算 + `y` 轴翻转 + `w` 做前后判定，三行搞定，且对透视/正交投影都成立。

**我们的改写**：放进 `render/RenderContext#project(Vec3)`，`camera.pos` 来自 `CameraRenderState.pos`，`guiWidth/Height` 缓存到 `RenderContext` 里（避免每帧调 `getWindow()`）。

### 3.2 角度 → 安全区矩形边界交点

**上游**：`math/MathUtils.java:37-77`

```java
public static Vec2 calculateAngleRectIntersection(float angle, Vec2 leftTop, Vec2 rightBottom) {
    var direction = new Vec3(Math.cos(angle), Math.sin(angle), 0f);
    var width  = rightBottom.x - leftTop.x;
    var height = rightBottom.y - leftTop.y;
    direction = direction.multiply(new Vec3(1f / width, 1f / height, 0f));   // 归一化到矩形空间

    var dx = Math.cos(angle), dy = Math.sin(angle);
    var cx = width * 0.5f, cy = height * 0.5f;

    if (Math.abs(direction.x) < Math.abs(direction.y)) {
        if (direction.y < 0) { var t = -cy / dy; return new Vec2((float)(cx + t*dx) + leftTop.x, leftTop.y); }   // 上边
        var t = cy / dy;       return new Vec2((float)(cx + t*dx) + leftTop.x, rightBottom.y);                   // 下边
    }
    if (direction.x < 0) { var t = -cx / dx; return new Vec2(leftTop.x, (float)(cy + t*dy) + leftTop.y); }       // 左边
    var t = cx / dx;       return new Vec2(rightBottom.x, (float)(cy + t*dy) + leftTop.y);                        // 右边
}
```

**用途**：屏幕边缘方向箭头贴在安全区边框上，而不是贴在屏幕边缘（避开热键栏/血量）。

**单测点**：角度 0/90/180/270 应分别落在右/下/左/上边中点。

### 3.3 距离缩放

**上游**：`core/PingView.java:147-152`

```java
private void calculateScale() {
    final var scale = 2.0 / Math.pow(distance, 0.3);
    final var pingSize = CLIENT_CONFIG.getPingSize() / 100f;
    this.scale = (float)Math.max(1.0, scale) * 0.5f * pingSize;
}
```

**特点**：`distance^0.3` 让"远处缩小"非常缓慢（1 格 → 2.0，100 格 → 0.78，1000 格 → 0.39），且 `max(1.0, ...)` 保证 1 格内不放大到离谱。

### 3.4 射线拾取

**上游**：`math/Raycast.java:72-144`（`traceDirectional` + `traceEntity`）

关键点：
1. `ClipContext.Block.VISUAL` vs `OUTLINE`、`Fluid.NONE` vs `ANY` 由**是否潜行**切换（`Raycast.java:93-94`）——潜行时能穿过草丛/液体标到后面的实体；
2. 实体包围盒 `inflate(ent.getPickRadius()).inflate(0.25)`（L126-127）——比原版拾取稍微宽容一点，手感更好；
3. 方块与实体命中取**距离近者**（L109-113）；
4. 排除旁观者（L103）。

### 3.6 相机矩阵的"完整版"

**上游**：`mixin/GameRendererMixin.java:54-82`

```java
private Matrix4f PingWheel_calculateProjectionMatrix(CameraRenderState cameraState, DeltaTracker deltaTracker) {
    var optionsState = this.gameRenderState.optionsRenderState;
    var playerState  = this.gameRenderState.levelRenderState.playerRenderState;

    var projectionMatrix = new Matrix4f(cameraState.projectionMatrix);
    var bobStack = new PoseStack();
    this.bobHurt(cameraState, bobStack);                       // 受伤抖动
    if (optionsState.bobView) this.bobView(cameraState, bobStack);   // 视角摆动
    projectionMatrix.mul(bobStack.last().pose());

    // 反胃 / 传送门扭曲
    float spinningEffectIntensity = Math.max(playerState.portalEffectIntensity,
                                             playerState.nauseaEffectIntensity)
                                    * optionsState.screenEffectScale * optionsState.screenEffectScale;
    if (spinningEffectIntensity > 0.0F) {
        float skew = 5.0F / (spinningEffectIntensity * spinningEffectIntensity + 5.0F)
                   - spinningEffectIntensity * 0.04F;
        skew *= skew;
        Vector3f axis = new Vector3f(0.0F, Mth.SQRT_OF_TWO / 2.0F, Mth.SQRT_OF_TWO / 2.0F);
        float angle = playerState.spinningEffectAngle * ((float)Math.PI / 180F);
        projectionMatrix.rotate(angle, axis);
        projectionMatrix.scale(1.0F / skew, 1.0F, 1.0F);
        projectionMatrix.rotate(-angle, axis);
    }
    return projectionMatrix;
}
```

**为什么必须抄**：`CameraRenderState.projectionMatrix` 是**未含** bob/反胃修正的"干净"矩阵。
如果直接用它投影，玩家走路时（视角摆动）、受伤时、进传送门时，**标点会和世界错位**（看起来"飘"）。

**验证方法**：进下界传送门，看标点是否跟着画面一起扭曲。

### 3.7 过滤链（`acceptPingPacket`）

**上游**：`core/PingManager.java:71-101`

```
isCorrupt → player/level/connection 空 → channel 不匹配 → 超出 pingDistance
   → Game.execute(() -> { addOrReplacePing; playSoundInDimension; })
```

**我们的对应**（`PingSyncService` 收到轮询结果后）：
```
ping 解析失败 → 维度不匹配 → 超出 pingDistance → 超出 maxConcurrentPings
   → Minecraft#execute(() -> { repo.addOrReplace; 声音提示; })
```

### 3.8 绘制顺序与矩阵栈

**上游**：`render/OverlayRenderer.java:30-54` + `PingLocationRenderer.java:30-56`

- `pushMatrix()` 一次包住整个循环，每个标点内部再 `pushMatrix/popMatrix`；
- 按距离**降序**排序后绘制 → 近的盖住远的（`PingManager.java:68`）。

**为什么重要**：26.3 的 `Matrix3x2fStack` 是**有状态**的，漏一个 `popMatrix` 会让后续所有 HUD 元素错位（包括原版的血条/热键栏）。
