> 状态：v1.1（2026-11-02 修订）｜实现方：客户端 `VMPing-mod` + 后端 `VMTools-Web`（`vmtools-next`，`/api/ping`）

> 2. §5：**服务端回显发送者自己的标点**（`pings` 含自己）；客户端按服务端 `id` 去重（POST 201 返回 id/seq 后立即替换本地占位）。

## 0. 为什么需要中继

原版（vanilla）Minecraft 服务端**不会**把 A 客户端发的东西转发给 B 客户端：
`ServerboundCustomPayloadPacket` 到了原版服务端只会被丢弃/忽略，没有"客户端之间"的通道。
所以「服务器不装 mod、只装客户端 mod、标点多人可见」只有一条路：**服务器之外的中继**。

VMPing 复用 VMFashion 已经验证过的通信范式（MC 账号 serverId 认证 → Bearer token → HTTP/JSON），
后端就是 VMTools-Web（`vmtools-next`）已有的 FastAPI 服务，新增 `/api/ping` 一组路由。

## 1. 通用约定

| 项 | 约定 |
|---|---|
| Base URL | 可配置，默认 `https://www.venusyu045.cn/api/ping` |
| 编码 | UTF-8 JSON（`application/json; charset=utf-8`） |
| 时间 | 毫秒时间戳（Unix epoch），服务端时间为准 |
| 鉴权 | `Authorization: Bearer <token>`（认证接口除外） |
| 客户端标识 | `X-VMPing-Version: <mod version>`（服务端只记日志，不做版本强校验） |
| 错误体 | `{"detail": {"code": "<code>", "message": "<人类可读>"}}`，兼容 FastAPI 的 `{"detail": "..."}` |

错误码（`detail.code`）：

| code | HTTP | 含义 | 客户端处理 |
|---|---|---|---|
| `unauthorized` | 401 | 缺 token / token 过期 | 重新认证一次，仍失败则降级本地 |
| `bad_token` | 401 | token 无效（签名/受众不对） | 同上 |
| `rate_limited` | 429 | 标点太频繁（带 `Retry-After` 秒） | 本地照常显示，提示"太频繁" |
| `room_full` | 429 | 房间标点容量满 | 本地照常显示 |
| `bad_request` | 400 | 参数越界（坐标 NaN、kind 未知、维度过长） | 记日志，不重试 |
| `server_busy` | 503 | 全局长轮询并发已达上限（带 `Retry-After` 秒） | 退避重试（不算熔断失败） |
| `server_error` | 500 | 服务端内部错误 | 退避重试 |

## 2. 认证（与 VMFashion 的 serverId 挑战同构）

后端复用 `core/fashion_auth.py` 的挑战表与 hasJoined 校验逻辑，**token 受众为 `ping`**。

### 2.1 申请挑战

```
POST /auth/challenge
{"mcUuid": "069a79f4-44e9-4726-a5be-fca90e38aaf5", "mcName": "Notch", "authServer": ""}
→ 200 {"serverId": "1f3c...", "expiresIn": 120}
```

- `authServer`：皮肤站（authlib-injector / Yggdrasil）地址；正版留空
- `serverId`：一次性、TTL 120s、绑定来源 IP

### 2.2 会话服务器 join（客户端直接调 Mojang / 皮肤站，不经我们后端）

```
POST <sessionServer>/session/minecraft/join
{"accessToken": "...", "selectedProfile": "<uuid 无横线>", "serverId": "<上一步的 serverId>"}
```

- 正版 sessionServer = `https://sessionserver.mojang.com`
- 皮肤站 = `authlib-injector` 探测到的 base（VMFashion 的 `FashionAuth.detectAuthServer` 可直接复用）

### 2.3 换 token

```
POST /auth/verify
{"mcUuid": "...", "mcName": "...", "authServer": "", "serverId": "1f3c..."}
→ 200 {"token": "<opaque>", "expiresAt": 1730086400000, "mcUuid": "...", "mcName": "...", "authType": "mojang"}
```

- 后端反查 `hasJoined?username=&serverId=`，**比对 UUID**，一致才签发
- token 的 JWT `aud` 固定为 `ping`（与时装 token 的 `fashion` 隔离：时装 token 调 ping 接口 → 401 `bad_token`，反之亦然）
- token 有效期 24h；客户端落盘到 `config/vmping/session.json`，过期前 60s 自动重认证
- 客户端**只在 https 下发送凭据**（明文 http 一律拒绝，与 VMFashion 的 `insecure_backend` 一致）

## 3. 房间（Room）

房间 = 一个「服务器 × 维度」的临时空间，**纯内存**，不落库、不迁移。

```
roomId = hex(sha256(normalizedServerAddress))[0:16]
```

`normalizedServerAddress` 归一化规则（客户端计算，服务端只当字符串）：

| 场景 | 取值 |
|---|---|
| 多人服务器 | `client.getCurrentServer().ip` 去空白、转小写；缺端口时补 `:25565` |
| 单机 | **不同步**（只本地标点，不发起任何网络请求） |
| 局域网 | **不同步**（v1；v2 可考虑用世界种子 + 端口做房间键） |
| 未连接 | 不标点 |

- 维度是**消息字段**而不是房间键：同一服务器的不同维度共用房间，客户端按 `dimension` 过滤渲染
- 房间 60 秒无活动即回收；全局房间数上限 1000（见 §6，v1.1 收紧）

> 安全说明：roomId 由服务器地址推导，知道地址且持有任意有效 MC 账号的人可以订阅该房间的标点。
> 标点 TTL 只有 20 秒、且本就是"喊给同服玩家看"的信息，v1 接受这个暴露面；
> 需要私密时后续加"房间口令"（`roomSecret`）字段，向后兼容。

## 4. 发送标点

```
POST /rooms/{roomId}/pings
Authorization: Bearer <token>
{
  "dimension": "minecraft:overworld",
  "x": 123.45, "y": 64.0, "z": -89.25,
  "kind": "default",                       // default | danger | item | go | help
  "targetUuid": "069a79f4-...",            // 可空：点到实体时带上
  "targetName": "Notch",                   // 可空
  "clientTime": 1730000000123
}
→ 201 {
  "id": "9f2c...", "seq": 42,
  "serverTime": 1730000000200,
  "expiresAt": 1730000020200
}
```

服务端校验：坐标有限（拒绝 NaN/Inf）、`|x|,|z| ≤ 3e7`、`|y| ≤ 2048`、`kind` 白名单、
`dimension` 长度 ≤ 128、`targetName` 长度 ≤ 64。服务端**不信**客户端时间，`serverTime` 为准。

## 5. 拉取标点（长轮询）

```
GET /rooms/{roomId}/pings?since=<seq>&timeout=20&dimension=<可选过滤>
Authorization: Bearer <token>
→ 200 {
  "seq": 45,
  "serverTime": 1730000001000,
  "pings": [
    {
      "seq": 43, "id": "9f2c...",
      "player": {"uuid": "...", "name": "Notch"},
      "dimension": "minecraft:overworld",
      "x": 123.45, "y": 64.0, "z": -89.25,
      "kind": "default",
      "targetUuid": null, "targetName": null,
      "serverTime": 1730000000200,
      "expiresAt": 1730000020200
    }
  ]
}
```

- `since` 缺省为 0（返回 TTL 内全部存活标点，用于重连补齐）
- 服务端最多等待 `timeout` 秒（默认 20，上限 25）：期间有新标点立即返回，否则超时返回空数组
- **`pings` 包含发送者自己的标点**（实现简单、无特例）：客户端用服务端分配的 `id` 去重 ——
  POST 201 返回 `{id, seq, serverTime, expiresAt}` 后立即用这条权威数据替换本地乐观占位，
  长轮询再收到同 `id` 时按 `id` 覆盖，不会出现两份
- **长轮询正常超时（200 + 空数组）不算失败**：不计入熔断、不触发退避，客户端立即发起下一次
- 返回的 `seq` 是**当前房间最大序号**，客户端下次用它做 `since`
- **房间被回收后重建时 `seq` 从 0/1 重新开始**：客户端收到 `seq < 本地 since` 时必须重置 `since=0`
  并清空本地他人标点，否则会永远收不到新标点
- 客户端同时只能有一个长轮询在飞；退服/切维度要主动 abort

## 6. 限流与容量（服务端默认值，可配置）

| 项 | 默认 | 说明 |
|---|---|---|
| 每玩家发送 | 5 条 / 3 秒（滑动窗口） | 超限 429 + `Retry-After` |
| 每房间存活标点 | 200 条 | 满了返回 `room_full` |
| 标点 TTL | 20 秒 | 惰性清理 |
| 房间空闲回收 | 60 秒 | 单 worker 内存现实 |
| 全局房间数 | 1000 | |
| 长轮询等待者/房间 | 64 | 超出立即返回空数组 |
| 全局长轮询并发 | 5000 | 超出 503 + `Retry-After`（`server_busy`） |
| 认证 challenge | 每 IP 20 次 / 60 秒 | 防刷 |

> 全部可用环境变量 `VMT_PING__*` 覆盖（见 `docs/后端实现.md`）。

## 7. 客户端行为约定

1. 进服（`ClientPlayConnectionEvents.JOIN`）→ 认证 → 算 roomId → 启动长轮询
2. 按键（默认**鼠标中键**）按下 → 打开轮盘；移动鼠标选类型；松开 → 立即本地渲染 + 异步 POST
3. 发送失败：本地标点保留（标记"仅本地"），状态栏提示，不弹窗刷屏
4. 退服 / 切维度：停止轮询、清空他人标点（自己的短时保留）
5. 后端不可达：整体降级为纯本地标点（功能可用，只是别人看不见）
6. 渲染：标点 TTL 内显示（20s），最后 3 秒淡出；距离 > 64 格显示屏幕边缘箭头
